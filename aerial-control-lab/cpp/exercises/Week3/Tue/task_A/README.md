# Task A：STL 容器对照表

> 本表中的 `n` 表示容器当前的元素数量。复杂度描述的是容器本身的主要操作；如果比较一个键本身也很昂贵，还需要额外考虑键比较或哈希的成本。

## 八类容器对照

| 容器 | 主要用途 | 访问/查找 | 插入删除 | 是否连续内存 | 典型失效规则 |
|---|---|---|---|---|---|
| `std::array<T, N>` | 编译期固定长度的数据，例如三轴状态 | 下标访问 `O(1)`；无序按值查找 `O(n)` | 长度固定，不支持增加或删除元素；修改已有元素 `O(1)` | 是 | 不发生扩容；普通元素赋值不会使指针、引用或迭代器失效。对象生命周期结束后，它们全部失效 |
| `std::vector<T>` | 运行期动态增长的连续数据，例如仿真日志 | 下标访问 `O(1)`；无序按值查找 `O(n)` | 尾部添加均摊 `O(1)`、发生扩容时单次最坏 `O(n)`；中间插入和删除 `O(n)` | 是 | 重新分配内存后，所有旧指针、引用和迭代器失效；未重新分配时，插入点及其后的迭代器和引用失效；`erase` 使被删位置及其后的迭代器和引用失效 |
| `std::deque<T>` | 双端队列、固定容量滚动缓存 | 下标访问 `O(1)`；无序按值查找 `O(n)` | 两端添加和删除 `O(1)`；中间插入和删除 `O(n)` | 否，不保证为一整块连续内存 | 两端插入通常使所有迭代器失效，但不会使已有元素的引用和指针失效；中间插入会使迭代器和引用失效；只在两端删除时，通常只有被删元素失效 |
| `std::list<T>` | 需要稳定节点地址，并在已知位置频繁插入或删除 | 不支持下标；访问或查找第 `n` 个元素需要 `O(n)` | 已知迭代器位置时插入和删除 `O(1)`；寻找位置本身可能是 `O(n)` | 否，元素位于独立节点中 | 插入通常不使已有指针、引用和迭代器失效；删除只使指向被删节点的指针、引用和迭代器失效 |
| `std::map<Key, T>` | 需要按键排序的键值数据 | `find`、`at` 和 `operator[]` 为 `O(log n)`；`operator[]` 在键不存在时会插入默认值 | 插入和删除 `O(log n)` | 否，通常为基于节点的平衡搜索树 | 插入不使已有指针、引用和迭代器失效；删除只使被删元素失效 |
| `std::unordered_map<Key, T>` | 不要求键有序的键值存储和频次统计 | 平均 `O(1)`，最坏 `O(n)` | 插入和删除平均 `O(1)`，最坏 `O(n)`；重新散列需要重新组织桶 | 否，不保证连续 | `rehash` 使所有迭代器失效，但不会使已有元素的指针和引用失效；未触发 `rehash` 的插入不使迭代器失效；删除只使被删元素失效 |
| `std::set<Key>` | 保存不重复且按键有序的集合 | `find` 为 `O(log n)`；不支持下标 | 插入和删除 `O(log n)`；插入重复键不会增加元素 | 否，通常为基于节点的平衡搜索树 | 插入不使已有指针、引用和迭代器失效；删除只使被删元素失效；不能通过迭代器修改键 |
| `std::priority_queue<T>` | 动态维护最高优先级元素，例如最大误差或 Top-K | `top()` 为 `O(1)`；不提供随机访问、遍历或任意元素查找接口 | `push`/`emplace` 和 `pop` 为 `O(log n)` | 接口不保证；默认底层容器是 `vector`，但不暴露连续存储接口 | 不公开迭代器；`push` 或 `pop` 后不应继续依赖此前由 `top()` 获得的引用 |

## 复杂度术语

- `O(1)`：操作量基本不随元素数量增长，例如 `vector[i]`。
- `O(log n)`：每一步排除一部分候选，例如平衡搜索树查找。
- `O(n)`：最坏需要检查或移动全部元素，例如无序查找或 `vector` 头部删除。
- 平均 `O(1)`：对通常的键分布和哈希行为取平均；不排除哈希冲突导致的 `O(n)` 最坏情况。
- 均摊 `O(1)`：一系列操作的平均成本为常数；单次 `vector::push_back` 在扩容时仍可能是 `O(n)`。

## 关键选择依据

### 为什么 `vector` 缓存友好

`vector` 将元素连续存放。顺序遍历时，相邻元素的地址也相邻，处理器可以高效预取连续数据，并让一个缓存行同时包含多个元素。它通常比逐节点跳转的容器更适合数值数据和顺序扫描。

### 为什么 `list` 不一定比 `vector` 快

`list` 只有在已经持有目标位置迭代器时，插入和删除才是 `O(1)`。寻找目标位置仍可能是 `O(n)`；每个节点还需要链接信息和独立存储，遍历时缓存局部性通常较差。元素较少或需要顺序处理时，`vector` 即使需要搬移，也可能更快。

### 为什么不能假设 `unordered_map` 有序

`unordered_map` 根据键的哈希值把元素放入桶中。插入、删除或 `rehash` 都可能改变桶的数量和遍历顺序；即使内容相同，不同实现或不同运行条件下也不能依赖某个固定顺序。

### 为什么 `priority_queue` 不能随机访问

`priority_queue` 是容器适配器，只公开 `top`、`push`、`emplace`、`pop`、`size` 和 `empty` 等优先队列操作。它只维护堆的局部顺序，保证 `top()` 是当前最高优先级元素，并不维护一个可供用户随机访问的完整有序序列。

## 常用 API 查询方法

查询时使用“容器全名 + 成员函数 + cppreference”，例如：

```text
cppreference std::vector push_back
cppreference std::vector iterator invalidation
cppreference std::unordered_map rehash
cppreference std::priority_queue top
```

优先查看页面中的成员函数说明、复杂度（Complexity）和迭代器失效（Iterator invalidation）部分。`std::array` 来自 `<array>`，`std::vector` 来自 `<vector>`，`std::deque` 来自 `<deque>`，`std::list` 来自 `<list>`，`std::map` 来自 `<map>`，`std::unordered_map` 来自 `<unordered_map>`，`std::set` 来自 `<set>`，`std::priority_queue` 来自 `<queue>`。
