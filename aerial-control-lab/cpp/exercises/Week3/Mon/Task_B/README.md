# Week3 周一任务 B：值传递与引用传递

## 值传递

- 运行前预测：未在运行前写入 README；预期函数内部的形参会变为 `99`，调用结束后调用者的变量仍为 `10`。
- 实际结果：函数内部的形参由 `10` 变为 `99`，调用结束后调用者的变量仍为 `10`。
- 原因：值传递会拷贝一个副本。函数修改的是形参副本，不是调用者原来的变量。
- 调用者是否被修改：否。

## 引用传递

- 运行前预测：未在运行前写入 README；预期函数内部和调用结束后，调用者的变量都会变为 `99`。
- 实际结果：函数内部的值由 `10` 变为 `99`，调用结束后调用者的变量也变为 `99`。
- 原因：引用传递不会为参数创建独立副本，形参是调用者变量的别名，对引用的修改就是对原变量的修改。
- 调用者是否被修改：是。

## `const` 引用

- 运行前预测：未在运行前写入 README；预期函数能够读取调用者的变量，但不能通过 `const` 引用修改它。
- 实际结果：函数能够正常读取变量；临时写入 `value = 99` 时无法通过编译，恢复只读实现后构建成功。
- 原因：`const int&` 引用原对象而不创建独立副本，但 `const` 禁止函数通过该引用修改对象。
- 调用者是否被修改：否。

## 可空指针

- 运行前预测：未在运行前写入 README；预期传入 `&pointer_value` 时能够修改原变量，传入 `nullptr` 时跳过修改且程序不会崩溃。
- 实际结果：传入有效地址后，原变量由 `10` 变为 `99`；传入 `nullptr` 后进入空指针分支，没有解引用，也没有发生崩溃。
- `value`：指针变量，保存所指对象的地址，也可能为 `nullptr`。
- `*value`：对非空指针解引用后得到的原对象。
- `&pointer_value`：取得调用者变量的地址。
- 空指针检查：`if (value)` 表示指针非空；只有在该分支中才可以安全使用 `*value`。
- 为什么不使用 `NULL`：现代 C++ 使用类型更明确的 `nullptr` 表示空指针。

## 按值返回局部对象

- 实现：`make_status_message()` 在函数内创建局部 `std::string`，随后按值返回并由调用者输出。
- 实际结果：调用者成功得到并输出 `Status: OK`。
- 原因：按值返回会用局部对象的值初始化返回结果；编译器可以使用返回值优化，否则使用移动或复制。函数返回后，调用者持有的是有效的结果对象，而不是已经销毁的局部对象引用。
- 结论：返回 `T` 通常安全；返回局部对象的 `T&` 或 `T*` 会产生悬空引用或指针。

## `unique_ptr` 所有权移动

- 运行前预测：移动前 `first` 独占对象；执行 `std::move(first)` 后，`first` 为空，`second` 成为唯一所有者；`second` 离开作用域时自动销毁对象。
- 实际结果：移动前通过 `first` 输出 `owned resource`，移动后 `first` 分支不再执行，通过 `second` 仍能输出 `owned resource`。
- 为什么不能复制：复制会破坏唯一所有权，使多个独占指针同时认为自己负责释放同一个对象；`unique_ptr` 因此禁用复制并允许移动所有权。
- 为什么可以移动：移动只改变唯一所有者，不复制被管理对象；源 `unique_ptr` 变空，目标 `unique_ptr` 接管销毁责任。
- 最终释放：`second` 离开作用域时，其析构函数自动销毁所管理的 `std::string`。
- 验收等级：H。实现采用了自行组织的判断和输出结构，构建、运行及所有权解释均通过。

## 对比结论

值传递传入的是副本，因此函数返回后调用者仍为 `10`；引用传递不复制对象，而是通过别名访问原对象，因此函数返回后调用者变为 `99`。
